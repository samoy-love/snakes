# Визуальные регрессионные тесты (`screens.spec.mjs`) временно отключены

Решение владельца. Отключено в двух местах:

- `screens.spec.mjs` — оба `test.describe` обёрнуты в `.skip`.
- `.github/workflows/ci.yml`, задача `visual` — реальные шаги заменены на
  один `echo`; `make test-visual` (Makefile) тоже печатает сообщение и
  выходит без прогона.

Job `visual` в CI намеренно **не удалён и не переименован** — только
опустошён. Удаление job целиком роняет обязательную проверку ветки `main`
по имени (см. комментарий у `protection-sync` в `ci.yml`): защита ветки
ищет проверку по названию в API прогона, не находит её и блокирует все PR
до ручной правки в Settings → Branches. Пустой job с тем же именем этого
избегает — CI остаётся зелёным без реального прогона.

## Почему

Широкий каталог ревью (`docs/reviews/review-loop-prompt.md`) строится
параллельно и по замыслу меняет геометрию HUD/оверлеев на каждой итерации
цикла «съёмка → ревью → починка». Пиксельный гейт с эталонами
(`toHaveScreenshot`, два набора — win32 и linux) на нестабилизировавшейся
раскладке означал бы ре-бейзлайн этих шести состояний почти на каждой
итерации — дороже пользы, пока раскладка не выйдет из фазы активных правок.

## Как включить обратно

1. Убрать `.skip` у обоих `test.describe(...)` в `screens.spec.mjs`.
2. В `Makefile`, цель `test-visual` — вернуть реальные шаги
   (`$(NODE) tests/visual/free-ports.mjs` + `npm install` + `npx playwright test`).
3. В `.github/workflows/ci.yml`, задача `visual` — вернуть полный набор
   шагов (checkout → setup-go → setup-node → npm ci → кэш браузеров →
   install → `make test-visual` → артефакт упавших тестов при `failure()`).
   Проще всего — откатить конкретный коммит, отключивший эти три места,
   поверх текущего состояния (`git revert`), а не переписывать заново: диф
   отключения умещается в один коммит.
4. Если за время отключения `VIEWPORTS` в `playwright.config.mjs` menялся
   (новые разрешения — см. `docs/reviews/review-loop-prompt.md`, раздел 2) —
   у `screens.spec.mjs` не будет эталонов для новых вьюпортов. Прогнать
   `make test-visual-update` (или GitHub Actions → «Обновить эталоны
   визуальных тестов», `update-visual-snapshots.yml`, для linux-набора),
   просмотреть новые кадры глазами, закоммитить эталоны отдельным,
   осознанным изменением — не вместе с включением тестов обратно.
