# Конфигурация

Все настройки приходят из окружения. Шаблон для копирования — `.env.example`
в корне; здесь то же самое таблицей, с дефолтами и причинами.

Тест `env_docs_test.go` следит, чтобы каждая `os.Getenv` в неотладочном коде
была описана и в этом файле, и в шаблоне, а в шаблоне не осталось переменных,
которых код уже не читает.

| Переменная | Дефолт | Описание |
| --- | --- | --- |
| `PORT` | `3000` | Порт HTTP/WebSocket-сервера |
| `BIND_ADDR` | `127.0.0.1` | Интерфейс привязки. Дефолт — только loopback: снаружи сервер доступен через nginx, напрямую — нет |
| `ROOM_LIMIT` | `16` | Максимум живых игроков в комнате (боты считаются отдельно) |
| `MATCH_DURATION_TICKS` | `3000` | Длительность матча в тиках (тик = 100 мс, то есть 5 минут) |
| `MATCH_INTERMISSION_TICKS` | `150` | Пауза между матчами в тиках |
| `WS_ORIGINS` | `http(s)://snakes.samoy.love` | Origin'ы, которым разрешено рукопожатие `/ws`. Остальным — 403 |
| `WS_ALLOW_LOCALHOST` | `0` (выключено) | Пропускать ли loopback-origin мимо allowlist. Включается значениями `1`, `true`, `yes`, `on`; **любое другое значение = выключено**. В проде включать нельзя — иначе любая локально запущенная страница получает валидный Origin |
| `WS_MAX_CONNS_PER_IP` | `0` (без потолка) | Потолок одновременных `/ws`-соединений с одного адреса. `0` — не ограничивать: процесс слушает loopback за прокси, который держит лимиты сам, а локальные прогоны открывают десятки соединений с `127.0.0.1`. Ставится, если порт выставлен наружу |
| `PROFILE_SECRET` | *(случайный)* | HMAC-ключ подписи токенов личности. **В проде задавать обязательно**, см. [безопасность](security.md) |
| `PROFILE_SECRET_REQUIRED` | `0` (выключено) | Валить старт, если `PROFILE_SECRET` пуст, вместо эфемерного ключа и потери прогресса игроков. На проде включён дроп-ином `deploy/systemd/snakes.service.d/20-profile-secret.conf` — предписание больше не живёт только в этой строке. Включается значениями `1`, `true`, `yes`, `on` |
| `PROFILES_PATH` | `./data/profiles.json` | Путь к файлу профилей. На проде — `/var/lib/snakes/profiles.json` |
| `TRUSTED_PROXIES` | `127.0.0.1/8,::1` | Чьему `X-Forwarded-For` можно верить |
| `MAX_ROOMS` | `64` | Потолок числа живых комнат (~500 КБ каждая) |
| `MAX_PROFILES` | `50000` | Потолок числа профилей: сохранение маршалит весь набор целиком |
| `PROFILE_EMPTY_TTL_HOURS` | `6` | Через сколько часов вычищается профиль без прогресса (с прогрессом — 90 дней) |
| `BOT_DEATH_SNAP` | *(пусто)* | Отладочный «снап» бота при смерти. В проде не нужен |
| `METRICS_ADDR` | *(пусто)* | Адрес отдельного слушателя метрик (`host:port`). Пусто — отдельного слушателя нет, см. [метрики](metrics.md) |

## Что сервер печатает при старте

Фактические лимиты и версия сборки уезжают в лог первой строкой:

```
snakes build version=... commit=... buildTime=...
limits roomLimit=16 maxRooms=64 maxProfiles=50000 wsAllowLocalhost=false
```

Версия вшивается линкером (`-X main.Version=...`) на выкатке и отдаётся клиенту
в пакете `hello` и в `/version.json`. Ручная `go build` без `-ldflags` даёт
`version=dev` — на проде это означает, что бинарь собран мимо пайплайна.
